# PC·모바일 반응형 UI/UX 개선 설계

## 목표

LLM COMPASS의 전문가용 고밀도 대시보드 성격과 현재 기능을 유지하면서, PC·태블릿·모바일 전반의 정보 계층, 내비게이션, 상호작용, 접근성을 일관된 체계로 개선합니다.

## 범위와 원칙

이번 설계는 앱 공통 셸과 모든 주요 화면의 반응형 UX 기준을 다룹니다. 기능을 줄이거나 대중적인 단순 화면으로 전환하지 않습니다. 데이터의 양은 유지하되 사용자가 요약에서 상세 정보로 자연스럽게 이동할 수 있도록 계층을 정리합니다.

기존 화면을 한 번에 다시 만드는 대신 공통 기반부터 점진적으로 교체합니다. 뉴스 파이프라인 안정화와 별도의 구현 계획으로 진행하며, 현재 미커밋된 뉴스 상세 화면 변경을 보존합니다.

## 선택한 접근

### 점진적 고밀도 개선

기존 기능과 화면을 유지하면서 공통 레이아웃, 내비게이션, 카드, 표, 폼, 모바일 패턴을 통일합니다. 화면별 부분 개선은 UX 규칙의 불일치를 남기고, 전체 재설계는 회귀 위험과 작업 범위가 지나치게 크므로 선택하지 않습니다.

## 반응형 기준

- 모바일: 360~767px
- 태블릿: 768~1279px
- PC: 1280px 이상
- 일반 콘텐츠 최대 폭: 1440px
- 데이터 표·비교 화면: 사용 가능한 전체 폭
- 최소 터치 영역: 44×44px
- 모바일 기본 본문 글자: 14px 이상
- 보조 정보 글자: 12px 이상

화면 폭만으로 기기를 가정하지 않습니다. 키보드, 마우스, 터치 입력을 모두 지원하고 콘텐츠가 확대되거나 번역 문자열이 길어져도 핵심 기능을 사용할 수 있어야 합니다.

## 공통 앱 셸과 내비게이션

### 단일 메뉴 정의

`SidebarNav`, `HeaderTopBar`, 기존 `Navbar`에 중복된 메뉴 표현을 하나의 `navigationConfig`로 통합합니다. 설정에는 메뉴 ID, 번역 키, 아이콘, 그룹, 배지, 모바일 핵심 메뉴 여부를 정의합니다. PC 사이드바, 모바일 드로어, 모바일 하단 내비게이션은 이 설정과 동일한 활성 상태를 공유합니다.

사용되지 않는 별도 `Navbar` 구현은 참조 여부를 확인한 뒤 제거합니다. 메뉴 추가나 이름 변경이 여러 컴포넌트에 중복되지 않도록 합니다.

### PC

- 1280px 이상에서는 240px 좌측 사이드바를 기본으로 사용합니다.
- 사이드바는 64px 아이콘 모드로 접을 수 있습니다.
- 접힘 상태는 로컬 저장소에 보존합니다.
- 상단 바에는 전역 검색, 비교함, 언어, 테마만 배치합니다.
- 화면 제목, 설명, 화면 전용 액션은 각 콘텐츠 헤더에 둡니다.
- 콘텐츠 성격에 따라 일반 최대 폭 또는 전체 가용 폭을 선택합니다.

### 태블릿

- 768~1279px에서는 접힌 아이콘 사이드바를 기본값으로 사용합니다.
- 복잡한 필터는 고정된 보조 열 대신 접을 수 있는 필터 패널로 제공합니다.
- 비교표와 차트는 콘텐츠 가용 폭을 최대한 사용합니다.

### 모바일

- 상단 바에는 메뉴 버튼, 축약 로고, 검색, 비교함만 표시합니다.
- 언어와 테마 설정은 드로어의 설정 영역으로 이동합니다.
- 카탈로그, 비교, 뉴스, TCO를 하단 고정 내비게이션으로 제공합니다.
- 나머지 기능은 햄버거 드로어 안에서 카테고리별로 제공합니다.
- 드로어는 초점 고정, ESC 닫기, 배경 터치 닫기, 명시적 닫기 버튼을 지원합니다.
- 화면 이동 시 드로어를 닫고 본문 상단으로 이동합니다.
- 브라우저 뒤로가기와 앞으로가기 상태를 유지합니다.
- iOS safe-area를 반영하고 하단 내비게이션 높이만큼 본문 여백을 확보합니다.

## 공통 콘텐츠 계층

모든 주요 화면은 다음 순서로 정보를 구성합니다.

1. 화면 제목과 데이터 상태
2. 핵심 지표와 결론
3. 검색·필터·정렬
4. 주요 데이터
5. 상세 설명과 근거

전문 데이터를 숨기거나 삭제하지 않습니다. 초기 화면에서 의사결정에 필요한 정보부터 보여주고, 긴 설명과 보조 지표는 상세 보기나 펼침 영역으로 이동합니다.

## 화면별 설계

### 모델 카탈로그

PC에서는 검색과 필터를 한 줄 도구 모음으로 제공하고 카드 밀도를 `Compact`와 `Comfortable` 사이에서 전환할 수 있게 합니다. 모델 카드의 기본 영역에는 모델명, 제공자, 가격, 컨텍스트, 대표 벤치마크, 비교 선택을 표시합니다. 긴 설명과 하드웨어 요구사항은 펼침 영역이나 상세 화면에 배치합니다.

모바일에서는 필터를 하단 시트로 열고 적용된 필터를 칩으로 표시합니다. 카드에는 가격, 컨텍스트, 대표 점수를 먼저 보여주고 나머지 정보는 펼쳐봅니다. 비교 대상이 하나 이상이면 선택 수와 비교 화면 이동 버튼을 하단 내비게이션 위에 표시합니다.

### 모델 비교·리더보드·GPU 표

PC에서는 헤더와 첫 식별 열을 고정하고 정렬 기준을 명확히 표시합니다. 숫자는 우측 정렬하며 가격, 토큰, 메모리 등 단위 표기를 통일합니다.

모바일에서도 데이터 관계를 보존하기 위해 표를 모두 카드로 변환하지 않습니다. 핵심 식별 열을 고정한 가로 스크롤 표와 행별 상세 펼침을 함께 제공합니다. 화면 가장자리의 음영과 짧은 안내로 추가 열이 있음을 알립니다.

### 뉴스 목록과 상세

PC에서는 대표 종합 리포트 한 건과 최신 리포트 그리드를 구분합니다. 직무 렌즈와 주제 필터는 목록 상단에서 쉽게 접근할 수 있게 합니다. 카드의 기본 영역에는 제목, TL;DR, 출처 수, 게시 시각, 주제를 표시합니다.

모바일에서는 한 열 목록으로 전환하고 이미지 높이를 줄여 제목과 요약 가독성을 우선합니다. 상세 본문의 읽기 폭은 PC에서 약 720~800px로 제한합니다. 핵심 요약, 목차, 출처는 본문과 구분된 보조 영역으로 구성합니다. 다중 원문은 모바일에서 큰 버튼을 반복하지 않고 출처명과 도메인이 보이는 접이식 목록으로 제공합니다.

### TCO·Architecture Advisor·Tokenizer

PC에서는 입력과 결과를 좌우로 배치하고 결과 요약을 스크롤 중에도 확인할 수 있게 합니다. 모바일에서는 입력을 의미 있는 단계별 섹션으로 나누고 하단 고정 실행 버튼을 제공합니다.

결과는 핵심 결론과 비용 차이를 먼저 보여준 다음 계산 근거, 차트, 권장사항을 펼칩니다. 화면 이동, 섹션 접기, 검증 오류가 발생해도 사용자가 입력한 값은 유지합니다.

### 튜토리얼 및 장문 콘텐츠

긴 탭 목록은 모바일에서 현재 선택이 분명한 가로 스크롤 또는 드롭다운으로 제공합니다. 코드 블록에는 복사 버튼과 가로 스크롤을 제공하며 본문 전체의 가로 폭을 늘리지 않습니다. 단계형 설명은 PC에서는 나란히, 모바일에서는 세로 순서로 표시합니다.

## 시각 체계

현재 Indigo·Cyan 중심 브랜드 색상과 라이트·다크 테마를 유지합니다. 화면마다 다른 그라데이션과 그림자는 줄이고 다음 의미 기반 토큰을 사용합니다.

- `surface`: 배경과 카드 단계
- `border`: 기본, 강조, 선택 경계선
- `text`: 기본, 보조, 비활성 텍스트
- `accent`: 브랜드와 활성 상태
- `success`, `warning`, `danger`: 결과와 오류 상태

카드 모서리, 내부 여백, 제목 크기, 배지 스타일은 제한된 공통 규격으로 통일합니다. 핵심 데이터에는 10px 이하의 글자를 사용하지 않습니다. 가격과 수치에는 고정폭 숫자 스타일을 적용합니다. 마우스 hover로만 제공하던 정보는 클릭과 키보드 포커스로도 확인할 수 있어야 합니다.

## 상태와 피드백

- 전체 화면 스피너 대신 최종 구조와 유사한 스켈레톤을 사용합니다.
- 오류 상태는 재시도 가능 여부, 대체 데이터 사용 여부, 마지막 갱신 시각을 구분합니다.
- 빈 결과에는 필터 해제 또는 이전 단계 이동처럼 해결 가능한 행동을 제공합니다.
- 비교 추가, 복사, 필터 적용, 저장 결과는 짧은 인라인 메시지 또는 토스트로 알립니다.
- 처리 중인 버튼은 중복 실행을 막고, 취소 가능한 요청에는 취소 동작을 제공합니다.
- 화면 전환 중 데이터와 스크롤 상태가 예상치 못하게 초기화되지 않도록 합니다.

## 접근성

- 아이콘만 있는 모든 버튼에 `aria-label`을 제공합니다.
- 활성 메뉴에는 `aria-current="page"`를 적용합니다.
- 모달, 드로어, 하단 시트는 초점 고정, 초점 복귀, ESC 닫기를 지원합니다.
- 모든 상호작용 요소에 명확한 `focus-visible` 스타일을 제공합니다.
- 색상만으로 상태를 구분하지 않고 아이콘과 텍스트를 함께 사용합니다.
- `prefers-reduced-motion`에서는 카드 이동, ping, 장식 애니메이션을 제거합니다.
- 인접한 터치 대상 사이에 충분한 간격을 둡니다.
- 표, 차트, Mermaid에 제목, 설명 또는 텍스트 대체 정보를 제공합니다.
- 드로어가 열린 동안 배경 스크롤과 배경 요소 접근을 차단합니다.

## 검증 기준

### 화면 크기

- 모바일: 360×800, 390×844, 430×932
- 태블릿: 768×1024, 1024×768
- PC: 1280×800, 1440×900, 1920×1080

각 크기에서 라이트·다크 테마와 한국어·영어를 검증합니다. 긴 번역 문자열, 빈 데이터, 오류 상태, 많은 비교 대상도 포함합니다.

### 자동 테스트

컴포넌트 테스트는 내비게이션 활성 상태, 사이드바 상태 보존, 모바일 드로어, 하단 내비게이션, 필터 하단 시트를 검증합니다.

Playwright는 다음 핵심 흐름을 검증합니다.

1. 모델 검색 → 비교 추가 → 비교 화면 이동
2. 모바일 메뉴 → 뉴스 이동 → 상세 진입 → 뒤로가기
3. TCO 입력 → 계산 → 결과 확인
4. 테마와 언어 변경 → 새로고침 → 상태 유지

핵심 화면에 axe 기반 접근성 검사를 적용합니다. 의도하지 않은 페이지 전체 가로 오버플로, 하단 내비게이션의 콘텐츠 가림, 44px 미만 터치 영역을 확인합니다.

### 성능

- 화면 단위 코드 분할을 적용합니다.
- Mermaid는 필요한 화면에서만 지연 로딩합니다.
- 모바일 초기 JavaScript 전송량을 줄입니다.
- 레이아웃 이동과 장시간 메인 스레드 점유를 측정합니다.
- 기능 회귀 없이 현재 빌드의 대형 메인 번들을 축소합니다.

## 적용 순서

1. 디자인 토큰과 공통 반응형 기준
2. 단일 내비게이션 설정과 앱 셸
3. PC 사이드바와 상단 바 정리
4. 모바일 드로어와 하단 내비게이션
5. 모델 카탈로그와 비교 화면
6. 뉴스 목록과 상세 화면
7. TCO, Advisor, Tokenizer 입력·결과 구조
8. 리더보드, GPU, 튜토리얼
9. 접근성 및 다국어 회귀 검증
10. 번들 분할과 성능 최적화

각 단계는 독립적으로 테스트하고 배포할 수 있어야 합니다. 공통 셸을 먼저 안정화한 뒤 화면별 개선을 진행합니다.

## 완료 조건

- PC, 태블릿, 모바일이 하나의 메뉴 설정과 활성 상태를 공유합니다.
- PC의 고밀도 데이터 탐색성이 유지됩니다.
- 모바일에서 모든 핵심 기능을 가로 페이지 오버플로 없이 사용할 수 있습니다.
- 하단 내비게이션과 고정 실행 버튼이 본문을 가리지 않습니다.
- 모든 주요 상호작용을 키보드와 터치로 수행할 수 있습니다.
- 핵심 화면의 자동 접근성 검사에 중대한 위반이 없습니다.
- 한국어와 영어의 긴 문자열에서도 메뉴와 핵심 데이터가 잘리지 않습니다.
- 주요 사용자 흐름의 컴포넌트 및 E2E 테스트가 통과합니다.
- Mermaid와 화면별 코드는 필요할 때 로딩되며 초기 번들이 현재보다 축소됩니다.
